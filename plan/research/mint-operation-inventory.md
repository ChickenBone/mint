# Mint operation-surface inventory (P0)

**Status:** source inventory, not an implementation specification. This records
the current Mint checkout's exposed operations and the rewrite plan's stated
dispositions. It does not define replacement schemas, preserve old wire
compatibility, or claim runtime/deployment behavior.

## Scope and evidence rules

This inventory covers Mint's Next.js HTTP/media routes, the native facade,
rendered Next.js page routes and server actions, realtime protocol, local and
remote worker interfaces, and the standalone catalog service. Rows group
related operations; route and action names are listed explicitly. Evidence
links point to repository source, not deployment observations. The source
inventory is not a claim that unlisted provider calls, routes, or consumers do
not exist.

**Source fact** means behavior visible in the cited current implementation.
**Target disposition** means only a decision in the rewrite plan:

- **Initial**: retain the capability in the rewrite's initial delivery/API
  coverage. It does not mean implemented, scheduled in P0, or wire-compatible.
- **Deferred**: retain in the capability inventory but defer execution or client
  integration, as stated by the plan.
- **Retired**: the plan explicitly removes the target integration/surface.
- **Unresolved**: a required target API contract remains design or implementation
  work; this label is not a substitute for a target disposition.

The plan names P0 as Mint-and-donor API union coverage, existing web
routes/actions, licenses and owned contracts; this document is the Mint half
only. Plan dispositions are sourced from [compatibility](../migration/compatibility.md),
[feature decisions](../migration/features.md), [target architecture](../architecture/target.md),
[Plex-free infrastructure](../architecture/plex-free.md), and [phases](../execution/phases.md).
The domain-owner references are the current [domain cards](../../agents/domains/README.md).

## Source facts, plan decisions, and open contract questions

### Source facts established by this inventory

- The current source has a native REST facade and typed client, but these do not
  establish compatibility with either installed Expo app after the rewrite.
- The native route allowlist and shared `MintApi` methods document server/client
  capability surface, not a complete callsite audit of either Expo repository
  or physical-device behavior.
- The Next.js pages and server actions are a separate UI/action surface from the
  HTTP endpoints. The plan requires preserving the web UI while replacing its
  backend wiring; it does not say to preserve direct Next.js domain/database
  imports as target architecture.
- Several current media/data routes use cookie sessions, bearer tokens, origin
  checks, private/no-store responses, bounded body/page sizes, explicit IDs,
  revisions or time units. These are route-specific facts, not one universal API
  policy; no route-wide cache, paging, idempotency or deadline claim is made.
- Current realtime delivery is Redis Pub/Sub. A health check, event publisher,
  or socket subscription is not evidence of durable event recovery.
- Worker queue names/types and the current volunteer/analysis protocols are
  current interfaces, not the selected PostgreSQL/pg-boss or future remote-worker
  implementation.
- Plex is still present in inspected worker/index/artwork and integration
  code. The target preference retires Plex dependency but preserves Mint local
  playback, artwork, library, acquisition and measured analysis responsibilities.

### Target decisions already in the plan

- Expand the API to cover the union of Mint and Audio-copy capabilities; deliver
  a runtime-validated typed SDK and rewire the existing Next.js web app without
  changing its UI/routes/interactions. See [compatibility](../migration/compatibility.md).
- Leave both Expo apps untouched; inventory their API capability needs only.
  API parity is not installed-mobile-client wire compatibility, and no old-route
  adapter is a fresh-install gate. See [compatibility](../migration/compatibility.md)
  and [phases](../execution/phases.md).
- Fresh installations have empty state; no old account, collection, library,
  provider credential, session, queued job or cache migration.
- Use separate API/WebSocket and local-worker processes with PostgreSQL/pg-boss;
  WebSocket updates require PostgreSQL-backed recovery. Remote download and
  analysis execution are deferred. See [decisions](../execution/decisions.md).
- Retire Plex target dependencies only after equivalent read-only import,
  playback, artwork, search, finalization and other stated gates; preserve local
  files and Mint collection semantics. See [Plex-free gates](../architecture/plex-free.md).

### Unresolved for later contract work

- Exact target tRPC procedures, DTOs, error envelopes, authorization predicates,
  pagination revisions/cursors, idempotency keys, cache policies, deadlines and
  request-size limits must be traced from owning schemas/helpers and then
  explicitly designed. This inventory does not translate limits or infer
  contracts from UI behavior alone.
- Realtime event replay/sequence, privacy filters, reconnect cursor and
  backpressure behavior are target implementation gates, not settled schemas.
- Exact REST media transport versus SDK control-plane split is not fully designed;
  the plan explicitly requires media Range/HEAD and allows REST/OpenAPI for
  concrete integrations.
- Remote-worker operation execution is deferred, but final target-facing
  contracts, versioning and lifecycle acceptance are not specified here.
- This inventory does not audit every upstream HTTP call, worker-to-provider
  protocol, implicit Next.js layout behavior, all generated OpenAPI behavior, or
  all consumers of legacy endpoints. Do not treat omitted implementation details
  as proof that no additional operation/consumer exists.
