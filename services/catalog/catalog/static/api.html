mintcatalog / APIOpenAPI schema ↗

Local catalog API.

Metadata and source-attributed relationships. No upstream keys.

Search

GET /v1/search?q=ambient&mode=lexical

Options: q (1–256 characters), mode=hybrid|lexical, limit=1..50, optional source (musicbrainz, apple, youtube, ytmusic, spotify, deezer, audius, archive, wikidata, soundcloud, openverse), kind=artist|album|song, country=global|us|…, and group_artists=true|false (default true).

Returns query, mode, results and has_more (retrieved candidates, not an exhaustive total). Hybrid uses local embeddings plus keyword search; dependency failures return 503. Request lexical mode explicitly to search without the vector store.

Artist results group explicit cross-provider identities before the limit, retaining the highest-ranked matching record plus canonical_id, providers and providers_truncated. Names alone never cause a merge. Use group_artists=false for individual source records. Albums and songs remain source-scoped.

Entity and graph

GET /v1/entities/{source:scope:kind:id}

Returns the entity, up to 100 explicit edges and source-scoped popularity signals, observed provider links and stored attribution annotations. Example key: youtube:global:song:abcdefghijk.

Artist details also include the canonical group and its stored provider records. Observed links expose their canonical_status; conflicting or excluded assertions do not merge groups.

GET /v1/console/graph/{key}

Returns a bounded, fetched-node relationship graph for inspection.

GET /v1/console/artist-network

Pages stored canonical artists with optional q, limit=1..20 and after from the response's next. Pass key to expand one artist; next then pages that artist's credited records.

Edges are shared stored song/album credits with source-linked evidence, not inferred similarity. Returns nodes, edges, focus, next, limits and truncated. Views cap at 180 artists/400 edges; credit and evidence lists are bounded, not exhaustive relationship totals.

Raw data browser

Open the read-only data browser for PostgreSQL tables, Qdrant payloads and individual stored vectors.

GET /v1/data/tables, /v1/data/postgres/{table} and /v1/data/vectors. Pages accept limit=1..50, optional exact (first primary-key value or vector entity key) and an opaque after cursor from the previous response.

GET /v1/data/vectors/{uuid} returns the stored floating-point vector. No arbitrary SQL, mutations or other collections are supported.

Health and live operations

/healthz · /readyz · /v1/console/snapshot

Connect to ws://localhost:8097/v1/console/live from the same origin for five-second telemetry snapshots. Use the console controls for seeding, source pause and retry; the OpenAPI schema describes their request bodies.

Loopback operator tool, not a public authenticated API. No external documentation scripts or CDN requests are needed.
