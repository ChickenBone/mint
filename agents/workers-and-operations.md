# Workers, deployment and operational lessons

## Different workers, different trust

| Component | Purpose and connectivity |
| --- | --- |
| Built-in pipeline worker | Indexing, acquisition/finalization, private media gateway and scheduling; private database/Redis/media access |
| Volunteer `mint-agent` | Downloads through its own Cobalt, outbound HTTPS claims/progress/uploads; approved registration token, no private library access |
| Separate `mint-analysis` | Measured audio processing over trusted private/VPN connectivity; distinct analysis secret, disposable leased media, no database/Redis/Plex credentials |

A volunteer token does not authenticate analysis. Volunteer counts do not measure built-in worker or analysis connectivity.

## Artist metadata queue

The built-in worker discovers library artists in small batches and enriches them through a dedicated BullMQ queue. It uses MusicBrainz for exact identity/type/relationships, Wikidata to locate an English Wikipedia summary (with attribution), and ListenBrainz for community listening counts and similar artists. Ambiguous names are not guessed; provider failures are persisted and retried. This queue reads metadata only, does not inspect media files, and is separate from measured audio analysis. The queue appears in the worker's existing queue health counts; no new API secret is required.

## Analysis behavior

Read `docker-compose.analysis.yml`, `apps/worker/src/analysis-worker.ts`, `analysis-http.ts`, and [analysis setup](../docs/self-hosting.md#optional-separate-analysis-machine).

- Local analysis is supported; operators can dynamically switch `executionMode` in `/app/manage?tab=analysis` between `"remote-only"` (offload all analysis to external workers; NAS acts strictly as coordinator), `"prefer-remote"` (external workers first when online within 60s, local fallback), and `"hybrid"` (NAS + external workers) without editing `.env` or recreating containers. Setting `ANALYSIS_REMOTE_ONLY=true` in the environment forces `"remote-only"`.
- A separate analysis secret must be strong, generated by the operator and kept off public services.
- Remote concurrency is 1-4 slots and still obeys global enable/pause, UTC schedule, concurrency, duration and time budgets.
- Per-worker telemetry (`completedCount`, `failedCount`, `avgDurationMs`, `activeTrackId`, `engineVersion`, `capabilities`, `lastError`) is recorded on `analysis_workers`, and remote result submissions use a 1 MiB body limit with bounded exponential-backoff retries on transient network/5xx failures.
- CPU/memory/container slots are separate controls; increasing one does not override the others.
- Full-library scans persist a cursor and enqueue in batches of 500 without a total-library cap. A completed queue-building scan does not mean all audio is processed.
- Backfill modes support `"missing"` (tracks with no completed analysis), `"upgrade-v1"` (queues `version: 1` tracks for `version: 2` while keeping their `v1` result readable until `v2` completes), and `"all"` (full reprocessing). Preserve pending/running work; cancellation stops bulk queueing and pending/running processing without deleting originals/completed measurements.
- Adding a powerful processor does not implicitly reprocess completed music.
- This offloads Mint measurements, not Plex's optional entitlement-gated sonic scans.

## Self-hosting and upgrades

Use the full [self-hosting guide](../docs/self-hosting.md) rather than copying an individual's deployment.

NAS users may have only a project editor, logs and container terminals. Offer UI steps and request the smallest useful evidence; do not repeatedly insist on unavailable SSH.

Keep the project storage path and custom mounts stable. Preserve PostgreSQL, Redis, generated secrets, service configuration and media. Never use volume/data deletion as a generic reset.

Pull images, obtain a fresh Plex claim only for a new unclaimed bundled server, and recreate it before the claim expires. Existing servers do not need new claims on updates.

Update the pipeline worker first and wait for migrations/health before updating web. A restart is not image recreation. Pulling an image does not update inline Compose configuration. Verify Release workflow completion before claiming GHCR images are available.

All-in-one Compose is the recommended complete deployment. Vercel cannot resolve Docker's private worker hostname and is not a drop-in native streaming/artwork solution; separately validate private connectivity and platform limits.

Android application distribution is separate: [EAS Build/Update](../docs/android-builds.md)
hosts APKs and compatible JavaScript/assets, not music or backend services.
There is no self-hosted OTA endpoint or storage dependency. Retain Android
signing credentials and `EXPO_TOKEN`; retire only obsolete custom OTA settings.
Gate updates on a finished APK matching the native fingerprint, production
channel/runtime and validated signer. EAS quotas apply. A queued build, verified
APK or published update is not proof of installation, cold-launch update
application, lockscreen artwork or background playback on a physical device.

## Networking lessons from troubleshooting

1. **Identify the layer before prescribing a fix.** PostgreSQL ready logs establish server startup, not worker DNS/routing. A correct Compose declaration does not prove a running network attachment.
2. **Container loopback is the container.** `localhost` is not the NAS or public web origin. Runtime-generated volunteer Compose and an explicit public `MINT_URL` prevent build-time localhost mistakes.
3. **Inspect deployment logs as well as application logs.** `EAI_AGAIN postgres` is a resolution symptom, not evidence of database corruption. A loopback-only container with no route has an attachment problem; public DNS cannot resolve private Docker aliases.
4. **Binding an IP requires ownership.** `cannot assign requested address` during port publishing means that address cannot be bound in Docker's host namespace. Confirm the real reachable host/interface; do not repeat an assumed LAN address.
5. **Port conflicts are a different error.** `address already in use`/`port is already allocated` calls for checking another host port, not resetting the database.
6. **Host/None modes are not repairs.** They remove the expected Compose network/service DNS behavior. Retain private bridge networks for worker, data services and any gateway.
7. **A proxy does not fix a disconnected upstream.** A separate LAN gateway still needs a working data-network attachment and healthy worker.
8. **Bound exposure deliberately.** Use an actual trusted private/VPN interface and restrictive firewall rules. LAN binding alone is not authorization; no router forwarding, public worker endpoint or Cloudflare route. HTTP on a LAN is unencrypted; use trusted connectivity appropriately.

Never promise recreating a container will fix DNS without evidence. Do not give commands that erase data or use static container IPs as an unexplained shortcut.

## Unresolved observation

A remote processor was reported to start, obtain an authenticated lease and later log `Analysis result not accepted fetch failed`. That identifies result submission/network failure, not its root cause or necessarily successful audio analysis.

No confirmed fix was established in this conversation. Correlate desktop, private gateway and pipeline logs/timestamps; distinguish transport failure from HTTP rejection, lease cancellation/expiry, worker restart and resource limits. Do not present later UI work as resolving it.
